# Управление через Telegram

Запуск с существующей авторизованной сессией аккаунта:

```bash
venv/bin/python live_agent.py
```

Остальные действия доступны в личном чате управляющего бота. `/start`
показывает постоянную клавиатуру возле поля ввода. Кнопка Telegram «Меню»
также содержит основные команды. Клавиатуру можно вернуть через `/start`,
если клиент Telegram её свернул.

## Новый диалог

1. «Диалоги» → нужный чат. До подтверждения ничего не индексируется.
2. Прочитать количество сообщений и описание платной обработки.
3. «Подготовить и открыть».
4. Бот импортирует доступную историю в один `chat_history.jsonl`, проверяет
   удаления, создаёт эпизоды и embeddings, анализирует историю частями,
   объединяет память, создаёт её индекс и собирает общий стиль.
5. После завершения активируются контекст, генерация и обработчики этого чата.

Вложения сохраняются в истории как тип, подпись и метаданные. Скачивание
всех медиа, распознавание фото и транскрипция голосовых в этот процесс не входят.

Во время подготовки работает кнопка «Подготовка»: там видны последний этап,
пауза и продолжение. После перезапуска нужно нажать «Продолжить». Сохранённые
результаты используются повторно; прерванный запрос, результат которого ещё
не сохранён, может выполняться заново. Стоимость зависит от модели и текста;
показанное количество частей — ориентир, а не денежная смета.

При переключении прежний обработчик отключается. Генерация во время подготовки
недоступна. Если подготовка завершилась ошибкой или была приостановлена,
активного диалога нет до успешного открытия. Истории и память остаются на диске.

## Существующий диалог

Готовая память загружается без полного повторного анализа. Новые сообщения и
эпизоды синхронизируются. «Память» → «Обновить память» запускает анализ через
тот же возобновляемый процесс; неизменённые сохранённые части не отправляются
в AI повторно. Для старого workspace, созданного прежними скриптами, этих
checkpoint может не быть: первое обновление потребует полного анализа.

«Память» → «Полный анализ истории» явно запускает этот процесс для всей истории,
в том числе существующего workspace. Ранее созданные вручную профили сохраняются.
Исходные анализы прежних скриптов остаются на диске; новые checkpoint находятся
в `chunk_analysis/pipeline_v1/` и не считаются взаимозаменяемыми со старыми.

## Изоляция и общий стиль

```text
data/account_<id>/
  global/
    user_style.json          # Общие характеристики формы речи
    style_sources.json       # Численные вклады диалогов, без цитат и фактов
    preparation_job.json     # Последняя задача подготовки
  dialogs/dialog_<id>/
    workspace.json
    chat_history.jsonl
    deleted_message_ids.json
    episodes.jsonl
    episode_embeddings_live.jsonl
    episode_pending_batch.json
    agent_memory.json
    memory_embeddings.json
    user_profile.json
    person_profile.json
    full_history_analysis.txt
    initialization_state.json
    memory_update_state.json
    chunk_analysis/pipeline_v1/
```

В каждой папке диалога остаются свои факты, эпизоды, отношения и профили.
Общий стиль собирается из собственных сообщений пользователя. Схема разрешает
только фиксированные значения длины, формальности, частоты эмодзи, пунктуации
и разбиения ответов. Свободный текст, имена, цитаты и факты в общий профиль
не принимаются. При генерации читается общий стиль только текущего аккаунта,
а память и эпизоды — только активного диалога. Настроение остаётся сессионным.

«Мой стиль» показывает общий профиль. Для существующей зрелой переписки его
можно впервые собрать кнопкой полного анализа; профиль конкретного человека
не копируется в глобальную папку.

Меню заменяется на месте; кнопки пульта выводят его ближе к последним сообщениям,
удаляя прежнее меню. Ответы, показанный контекст и входящие сообщения сохраняются.
Отправка ответов собеседнику автоматически не выполняется.
