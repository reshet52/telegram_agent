# Атлас файлов и изменений

[Начало](STUDY_GUIDE_RU.md) · [Порядок выполнения](execution_walkthrough_ru.md)

Сравнение с исходным checkpoint `af7c923` и текущими незафиксированными файлами.
«Новый» означает добавленный за предыдущие запросы этой сессии, а не уже
закоммиченный. Пустые `__init__.py` только обозначают пакеты; отдельной
пользовательской логики в них нет.

Большой отрицательный diff в `dialog_runtime.py` не означает исчезновение
подготовки. Часть обязанностей вынесена в отдельные файлы, консольная часть удалена.
`git diff --stat` без дополнительных действий не показывает содержимое новых
неотслеживаемых файлов — этим объясняется впечатление «много удалили, мало добавили».

## 2. Новые файлы интерфейса

### bot_keyboards.py — внешний вид кнопок

[Открыть](../mybot/telegram/bot_keyboards.py)

- `main_menu()` — шесть inline-кнопок.
- `home_menu(extra_rows)` — дополнительные действия и возврат домой.
- `dialogs_menu(dialogs, page)` — ограничение страницы, 8 чатов, стрелки навигации.
- `PANEL_ACTIONS` — словарь «текст кнопки → внутреннее действие».
- `control_panel()` — постоянная `ReplyKeyboardMarkup` возле поля ввода.

В этом модуле нет загрузки истории или AI-запросов. Хороший первый файл
для изучения функций: есть понятный вход и наглядный результат.

### bot_callbacks.py — маршрутизатор действий

[Открыть](../mybot/telegram/bot_callbacks.py)

- `handle()` — принимает callback от Telegram, проверяет владельца, подтверждает получение.
- `dispatch()` — выбирает действие по строке `ui:...`.
- `show_dialogs()` — получает список и строит страницу.
- `select_dialog()` — показывает информацию и сохраняет ожидаемое подтверждение.
- `show()` — передаёт служебный экран в `BotMenu`.

В `context.user_data` находятся кратковременные состояния интерфейса:
`ui_dialogs`, `pending_dialog`, `awaiting_mood`, `pending_full`.
Это не долговременная память о человеке и не гарантированно сохранённые на диск значения.

`dispatch()` вызывается как из callback, так и из обычного текста кнопки пульта.
Поэтому общая логика не должна быть написана дважды.

### bot_menu.py — одно служебное сообщение

[Открыть](../mybot/telegram/bot_menu.py)

Хранит ссылку на сообщение меню и блокировку его изменения.
`show()` редактирует существующее сообщение или создаёт новое, если редактирование
невозможно. Повторный одинаковый текст обрабатывается без ошибки для пользователя.

`move_to_bottom()` удаляет старое меню и освобождает ссылку, чтобы следующее
появилось возле последних сообщений. `clean_previous_menus()` распознаёт старые
служебные сообщения при запуске. Произвольные ответы и контекст не удаляются
по правилу «они старые».

### bot_panel.py — клавиатура и системная кнопка «Меню»

[Открыть](../mybot/telegram/bot_panel.py)

`install()` задаёт список команд Telegram, кнопку меню и постоянную клавиатуру.
`show()` отправляет сообщение с `ReplyKeyboardMarkup`, удаляя прежнее известное
сообщение пульта. Это отдельная обязанность от inline-меню: Telegram передаёт
нажатие такой клавиши обычным текстовым сообщением.

### bot_operations.py — защита действий активного диалога

[Открыть](../mybot/telegram/bot_operations.py)

`active_operation()` — декоратор. Его внутренняя функция `guarded()` проверяет
владельца, наличие сервиса ответов/workspace и `controller.busy`, затем удерживает
`controller.lock` на время действия. Сейчас он используется для контекста
и генерации. Обновление памяти отдельно запускается через координатор.

## 3. Новые файлы координации и подготовки

### runtime_controller.py — жизненный цикл активного диалога

[Открыть](../mybot/services/runtime_controller.py)

| Метод | Ответственность |
|---|---|
| `__init__` | Ссылки на аккаунт и бота; пустой runtime; загрузка последней задачи |
| `describe` | Предварительное описание диалога и объёма подготовки |
| `activate` | Проверка занятости, сохранение задачи, запуск `create_task` |
| `_activate` | Реальная последовательность подготовки и смены объектов |
| `clear_runtime` | Убрать ссылки на активные данные и сервис |
| `pause` | Отменить и дождаться фоновой подготовки |
| `resume` | Повторно запустить последнюю прерванную задачу |
| `stop` | Остановить подготовку и listener при выходе |

`job_path` расположен в общей папке аккаунта, потому что описывает текущую
операцию всего приложения. В нём может быть ID диалога и текст прогресса.
Это **не** часть общего стиля и не источник фактов для генерации.

В `AGENTS.md` центральная роль планировалась для `AgentManager`. В текущей
реализации жизненный цикл вынесен в отдельный `RuntimeController`, а
`AgentManager` оставлен небольшим каталогом Telegram-диалогов. На своей карте
рисуй оба объекта, не приписывай одному методы другого.

### history_import.py — порционный импорт

[Открыть](../mybot/services/history_import.py)

`import_history()` получает только сообщения после сохранённого ID. `commit_batch()`
собирает совместимое содержимое файла и фиксирует его атомарно. Порция — 200 записей.
Реальное преобразование сообщения переиспользуется из старого `telegram/exporter.py`.

### workspace_initializer.py — анализ и долговременная память

[Открыть](../mybot/services/workspace_initializer.py)

- `fingerprint()` — устойчивое имя результата по входу.
- `bounded_chunks()` — ограниченные части текста.
- `is_prepared()` — проверка собственного состояния `ready`.
- `has_legacy_memory()` — простая проверка наличия старых базовых файлов.
- `stage()` — запись этапа и сообщение прогресса.
- `cached()` — получить проверенный результат с диска или выполнить операцию.
- `run()` — учёт ошибки/паузы вокруг `_run()`.
- `_run()` — анализ, объединение, индекс, публикация профилей и состояния.
- `build_style()` — извлечение общих характеристик только из собственных сообщений.

Это самый насыщенный новый модуль. Читать его легче после понимания истории,
словарей, циклов, JSON, `await` и обработки исключений.

### global_style.py — контролируемое обобщение

[Открыть](../mybot/services/global_style.py)

`TRAITS` — разрешённая схема. `validate_traits()` отвергает произвольные значения.
`publish_style()` пересчитывает вклад диалогов. `load_global_style()` выдаёт
только разрешённые признаки текущего аккаунта.

Модуль не читает память всех собеседников для вставки в prompt. Общая папка
и локальные папки имеют разные задачи.

## 4. Новые файлы записи и восстановления

### storage/atomic.py

[Открыть](../mybot/storage/atomic.py)

`write_text()` создаёт временный файл рядом с целевым, записывает, вызывает
`flush` и `fsync`, затем `os.replace`. Файл находится в том же каталоге,
чтобы замена выполнялась в пределах той же файловой системы.

`write_json()` сериализует объект и использует тот же механизм.
`read_json()` возвращает значение по умолчанию только при отсутствии файла;
ошибка JSON не замалчивается как «пустые данные».

`durable_call()` выносит синхронную фиксацию в поток и дожидается её даже при
отмене внешней задачи. Атомарная замена одного файла не равна транзакции всех
файлов проекта и не является шифрованием.

### episodes/checkpoint.py

[Открыть](../mybot/episodes/checkpoint.py)

`pending_path`, `append_missing`, `recover_batch`, `commit_batch` реализуют журнал
между файлом эпизодов и файлом embeddings. Применение одной pending-порции можно
повторить без повторного добавления того же ID.

### episodes/maintenance.py

[Открыть](../mybot/episodes/maintenance.py)

`ensure_episode_embeddings()` сравнивает сохранённые эпизоды с base/live индексами
и создаёт недостающие записи. Этот путь не должен менять нумерацию эпизодов или
объявлять повреждённый tracker поводом для полного пересоздания истории.

|---|---|---|

| `episodes.jsonl` | Публикация эпизодов | Tracker при восстановлении, поиск эпизодов |
| `episode_embeddings.json` | Может существовать из прежней индексации | Поиск и проверка индекса |
| `episode_embeddings_live.jsonl` | Новая индексация и живые эпизоды | Поиск и восстановление |
| `episode_pending_batch.json` | `episodes.checkpoint` | Восстановление незавершённой публикации |
| `agent_memory.json` | Новый полный анализ | В первую очередь сохранённая читаемая база; генерация ищет по её индексу |
| `memory_embeddings.json` | Новый полный анализ | `memory.search` |
| `agent_memory_live.jsonl` | Прежний incremental-путь | Старые вспомогательные операции; новый полный анализ этот файл не дополняет |

| `user_profile.json` / `person_profile.json` | Новый анализ создаёт только отсутствующие файлы | `load_agent_memory` при подготовке runtime |
| `full_history_analysis.txt` | Новый анализ | Человек/отладка; не весь этот файл вставляется в каждый ответ |
| `ai_request_preview.txt` | `ReplyService.generate` | Человек/отладка; перезаписывается последним запросом |
| `memory_update_state.json` | Новый анализ и прежний updater | Учёт границы обработанных сообщений |
| `initialization_state.json` | Новый анализатор | Решение о готовности/продолжении |

В `global/`:

- `user_style.json` — разрешённые общие характеристики;
- `style_sources.json` — подсчёты вкладов диалогов, не тексты их фактов;
- `preparation_job.json` — последняя задача аккаунта и её прогресс; в prompt не вставляется.

## 8. Где появляются расходы и где их нет

| Действие | AI-запросы |
|---|---|
| Открыть список, страницу или настройки | Нет |
| Прочитать локальный JSON | Нет |
| Скачать историю Telegram | Нет OpenAI-запросов; есть Telegram-сеть |
| Посчитать cosine similarity готовых векторов | Локальное вычисление |
| Создать embeddings эпизодов или памяти | Да |
| Проанализировать новую часть истории | Да |
| Объединить ещё не закэшированную группу наблюдений | Да |
| Определить стиль ещё не закэшированной части своих сообщений | Да |
| Создать embedding текущего запроса для непустого индекса | Да |
| Сгенерировать варианты ответа | Да |
| Прочитать найденный результат из checkpoint | Нет нового AI-запроса для этой операции |

Указанные в `Config` значения — настройки проекта. Это не каталог актуальных
моделей или гарантия их доступности в любом аккаунте. Для выбора моделей и цен
следует отдельно обращаться к текущей официальной документации.

## 9. Тесты и доказательства

Новые тестовые файлы:

- [test_telegram_control.py](../tests/test_telegram_control.py): доступ владельца,
  меню, пульт, настроение, блокировки, смена runtime, отключение listener;
- [test_workspace_preparation.py](../tests/test_workspace_preparation.py):
  временные workspace, продолжение импорта/анализа, частичная запись эпизодов,
  пауза, разделение данных, ограничение общего стиля, новый и legacy-пути.

Тесты полезно читать как примеры входа и ожидаемого результата. `AsyncMock`
заменяет настоящий запрос, а `TemporaryDirectory` создаёт отдельную временную
папку. Проверка одного сценария не доказывает отсутствие всех возможных ошибок.

конфигурацию Codex и проверено его включённое состояние. Этот сервер помогает
помощнику читать документацию. `live_agent.py` его не вызывает; для работы
Telegram-бота он не является зависимостью.

## 11. Что создаётся только для обучения в текущем запросе

- `STUDY_GUIDE_RU.md` — входная точка;
- `execution_walkthrough_ru.md` — маршруты выполнения;
- `code_atlas_ru.md` — этот атлас;

инструкция. Учебная карта не запускает приложение, не читает личные данные
и не обращается к Telegram или AI.
