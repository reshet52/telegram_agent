# Подключение нескольких Telegram-аккаунтов

Установите зависимости из `requirements.txt`. В существующем `.env` оставьте `API_ID`, `API_HASH`, `SESSION_NAME` первого аккаунта, `AGENT_BOT_TOKEN` и `OPENAI_API_KEY`. Добавьте:

```dotenv
ALLOWED_TELEGRAM_IDS=111111111,222222222,333333333
PRIMARY_TELEGRAM_ID=111111111
```

Первый ID соответствует существующему файлу `mybot_session.session` (либо вашему `SESSION_NAME`). Файл не переносится. Для каждого дополнительного ID создайте отдельный локальный файл. Например, для третьего аккаунта — `data/account_333333333/global/telegram_credentials.json`:

```json
{
  "api_id": 12345678,
  "api_hash": "личный API_HASH третьего аккаунта"
}
```

Все Telegram ID и все API-пары должны различаться. Если пробный второй аккаунт больше не нужен, удалите **только его ID** из `ALLOWED_TELEGRAM_IDS`; его локальные данные и сессию сохраняйте. Папка `data/`, `.env` и файлы `.session` исключены из Git. Если первый аккаунт тоже входит впервые, его `API_ID` и `API_HASH` уже берутся из `.env`, а QR создаст его прежний файл сессии.

Запустите `python live_agent.py`. Управляющий бот запустится первым. Для аккаунта без действующей сессии откройте бота в приватном чате и нажмите «Войти по QR». QR сканируется через Telegram → Настройки → Устройства → Подключить устройство. Если включена 2FA, пароль вводится скрыто в локальной консоли. Код из Telegram отправлять боту не нужно.

После перезапуска приложение проверяет каждую сессию через Telegram и восстанавливает только готовый диалог без запуска анализа или embeddings. Приостановленную подготовку продолжайте кнопкой в боте. Бот не отправляет сообщения собеседникам.
