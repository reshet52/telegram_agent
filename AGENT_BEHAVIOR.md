# Поведение агента и отдельная модель ответов

## Управление в Telegram

Откройте диалог → «Цель диалога» → «Прямота, настойчивость и границы».

- Цель остаётся отдельной инструкцией владельца.
- Прямота: обычный персональный стиль или более прямые формулировки.
- Настойчивость: умеренная или более последовательное продвижение к цели.
- Ограничения и полномочия: что можно делать и чего нельзя обещать.
- Условие остановки: когда дальнейшее продвижение к цели не требуется.
- Текущее состояние: ваши актуальные намерения, настроение, доступность.
  Обновляется вручную, действует до изменения или очистки; не превращается в память.

Без сохранённых настроек действуют обычный стиль и умеренная настойчивость.
Настройки не включают автоматическую отправку. Прямота и настойчивость не означают
давление после отказа. Старые примеры не дают разрешения повторить действие сейчас.

Кнопка «Ответ», «Указания для ответа» и `/reply` запрашивают три варианта текста.
Они больше не заменяются рекомендацией подождать. Даже для завершённого разговора
запрашиваются уместные короткие варианты. Если модель нарушила формат, бот покажет
ошибку, а не карточку паузы. Все варианты остаются предложениями для владельца.

Внутренний режим выбора `reply`, `wait` или `ask_owner` сохранён с явным параметром
`allow_decision=True`, но обычная генерация и тренировка его не включают.

## Обратная связь

Под ранее созданными решениями есть оценки: «Подходит», «Не та реакция», «Не мой стиль»,
«Выдуманы факты». Последняя оценка заменяет предыдущую. Сводка находится в
«Цель диалога» → «Оценки ответов». Это ручные оценки, не независимый тест качества.

Оценка «Подходит» не означает отправку и сама по себе не создаёт обучающий пример.
Для использования правки по-прежнему нужно связать реально отправленные сообщения
с черновиком и завершить разметку. Отрицательная оценка исключает эту генерацию
из подбираемых примеров правок; она не удаляет сообщения и исторические эпизоды.
Веса модели автоматически не обучаются.

## Тренировка на имеющейся истории

Откройте диалог → «Тренировка на истории» → «Следующий отрывок» →
«Получить варианты». Нажатие выбора отрывка не вызывает модель; генерация делает
один вызов настроенного генератора. В чат собеседнику ничего не отправляется.

Выбирается случайная ещё не использованная ситуация перед серией исходящих сообщений.
Модель видит до 24 предшествующих текстовых сообщений (до 14 000 символов), включая
полную последнюю входящую серию. Вся следующая серия ответов владельца скрыта.
Отрывки с удалёнными сообщениями, медиа или слишком длинным контекстом пропускаются.
Ранее написанные владельцем сообщения внутри контекста служат примерами стиля.

Текущая память, профили, глобальный стиль, цели, состояние, исправления и поиск
похожих эпизодов не используются: они могли быть построены по будущей переписке.
Это проверка продолжения по ограниченному контексту, а не проверка полного агента
со всей его памятью. Скрытый ответ не передаётся модели даже после его открытия.

Тренировка показывает одну карточку: варианты переключаются кнопками 1/2/3,
контекст и длинные тексты открываются постранично в этой же карточке.
Каждый из трёх вариантов оценивается отдельно. «Мой реальный ответ» открывает
реальное продолжение для сравнения. Последняя оценка заменяет предыдущую;
оценки, поставленные после раскрытия ответа, помечаются отдельно. Сохранённый
результат повторно не генерируется при открытии или повторном нажатии кнопки.
При ошибке запроса можно явно повторить генерацию в том же отрывке.

Упражнения сохраняются в `reply_practice/<id>.json` внутри workspace диалога:
ID исходных сообщений, контрольная сумма источника, точный запрос, модель,
варианты, оценки и момент раскрытия ответа. История и рабочий журнал ответов
не переписываются. После удаления или изменения источника отрывок блокируется.
Сами сохранённые файлы упражнения при этом не удаляются автоматически.

## Как обратная связь влияет на рабочие ответы

Теперь обратная связь используется и до обучения весов:

- «Отправил бы» разрешает использовать вариант как одобренный пример.
- «Мой вариант» сохраняет написанное владельцем исправление для этой ситуации.
- После открытия реального ответа «Учиться на этом ответе» разрешает использовать
  именно реально отправленный исторический текст.
- «Не использовать как пример» отключает все примеры этого упражнения. Оценки
  остаются для проверки качества. Новая положительная оценка или новое исправление
  снова разрешают использование.

Из одного упражнения выбирается один пример: собственное исправление, иначе
явно выбранный реальный ответ, иначе последний одобренный вариант. Если оценка
варианта меняется на отрицательную, он больше не используется; другие одобренные
варианты того же упражнения по-прежнему могут использоваться.

В обычный запрос добавляется до трёх подходящих примеров вместе с существующими
подтверждёнными правками реально отправленных ответов. Подбор локальный, по общим
словам входящих сообщений; это ещё не семантический анализ ошибок. Примеры
помечаются по происхождению: предложенный/исправленный текст не выдаётся за
состоявшийся разговор. Правка не становится постоянным правилом стиля.

Используются только источники текущего диалога и аккаунта. Изменённые или удалённые
источники исключаются. Слепая историческая проверка по-прежнему не получает ни
эти примеры, ни рабочую память. При `USE_CORRECTION_EXAMPLES=false` примеры
не добавляются и в рабочую генерацию. Ранее сохранённые положительные оценки
тоже могут использоваться после обновления. Веса модели этим не меняются;
эффект на качество ответов требует отдельной оценки на реальных ситуациях.

## Подготовка настоящего дообучения

В тренировке есть «Локальное обучение» → «Подготовить набор».
Это локальная операция без API. Она создаёт новую версию в
`learning/datasets/<id>/` внутри workspace текущего диалога:

- `train.jsonl` — контекст и реальный ответ для обучения;
- `valid.jsonl` — отдельные поздние ситуации для проверки;
- `sources.json` — исходные ID и контрольные суммы;
- `manifest.json` — владелец, диалог, граница разделения, размеры и контрольные суммы файлов.

Последние 20% сообщений отводятся под проверку. Окна, пересекающие границу,
отбрасываются; между выборками нет общих исходных сообщений. Все исходные сообщения
упражнений ручной тренировки исключаются из обучающей части. Если после исключений
данных мало, подготовка останавливается, а не использует одни примеры дважды.
По умолчанию сохраняется не более 2000 примеров в каждой части. Старые версии
и исходная переписка не перезаписываются. Это техническое разделение данных,
а не гарантия разнообразия, качества или отсутствия похожих формулировок.

Скрипт `python -m scripts.train_reply_adapter --account ACCOUNT_ID --dialog DIALOG_ID
--dataset DATASET_ID` проверяет набор без загрузки модели. Используется окружение
проекта с его обычной конфигурацией. При изменённых/удалённых источниках или появлении
пересечения с новыми упражнениями требуется подготовить новую версию набора.

Для явного запуска добавляются `--train --model-path /путь/к/готовой/модели
--steps 100 --max-length 2048`. Обучающие зависимости перечислены отдельно в
`requirements-training.txt`: рабочему Telegram-боту они не нужны. Модель должна
быть уже скачана, иметь шаблон чата и поддерживаться Transformers/PEFT.
Скрипт не скачивает модель, не исполняет её remote code и не публикует данные.

LoRA обучается на конечном ответе владельца (`completion_only_loss`), а не на
репликах собеседника и не на всех промежуточных ответах в контексте. Примеры,
не помещающиеся в токенный предел, целиком пропускаются. Веса сохраняются в
`learning/adapters/<id>/adapter`; `run.json` фиксирует набор, базовую модель,
параметры, статус и validation loss до/после. Промежуточные checkpoints сохраняются;
автоматическое возобновление не реализовано. Набор и адаптер принадлежат одному
диалогу: не подключайте такой адаптер глобально ко всем чатам.

Снижение validation loss не доказывает, что ответы стали похожи на ваши.
Адаптер имеет статус `trained_unapproved` и не активируется автоматически.
Этот этап обучает один ответ по контексту; качество работы с рабочим промптом,
целями и форматом трёх вариантов ещё нужно проверять отдельно перед подключением.
Этот альтернативный TRL-скрипт на реальном оборудовании не проверялся.
Для текущего Mac используется отдельный MLX-процесс, описанный ниже.

Формат и интерфейс: [TRL SFTTrainer 0.29.0](https://huggingface.co/docs/trl/v0.29.0/en/sft_trainer).

## Хранение

В активном workspace при первом сохранении создаётся `dialog_behavior.json`
с account_id и dialog_id. Чужой или повреждённый файл блокирует использование
настроек; автоматического восстановления из другого диалога нет.

При следующем открытии журнала добавляются таблицы `generation_evidence` и
`generation_reviews` в существующий `reply_journal.sqlite3`. Прежние строки и
таблицы сохраняются. Новые генерации из Telegram записывают полный входной запрос,
системную инструкцию, модель, ID текущего контекста и решение. Старые записи
задним числом не дополняются. Снимки могут содержать личную переписку и увеличивают
размер журнала; они не экспортируются и автоматически не используются для обучения.

`ai_request_preview.txt` теперь содержит читаемый JSON со снимком запроса,
включая системную инструкцию; это тот же запрос, который отправляется модели.
API-ключи туда не записываются. Терминальный интерфейс показывает решения и пишет
этот preview, но разметка и журнал генераций доступны через Telegram.

## Модель ответов

По умолчанию используется прежний OpenAI Responses API и `OPENAI_MODEL`.
Переменная `REPLY_MODEL` может отдельно переопределить модель генерации ответов.

Для уже запущенного сервера, совместимого с Chat Completions API:

```dotenv
REPLY_PROVIDER=compatible
REPLY_BASE_URL=http://127.0.0.1:8000/v1
REPLY_MODEL=your-served-model
REPLY_API_KEY=
```

Адрес и имя модели должны соответствовать вашему серверу. Пустой ключ заменяется
служебным значением `local-no-key`; для сервера с авторизацией задайте отдельный ключ.
Ключ OpenAI никогда не подставляется в запрос к этому серверу. После изменения
настроек нужен перезапуск. Если сервер недоступен или ответ некорректен, генерация
завершается ошибкой без автоматического переключения на другого провайдера.

Сервер должен поддерживать `system`/`user` messages, `max_tokens` и возвращать текст
в `choices[0].message.content`. JSON решения проверяется локально. Совместимость
конкретного сервера и модели нужно проверить отдельно; модель не скачивается,
не запускается и не дообучается этим изменением.
Формат запроса: [официальная документация Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

**Это замена только генератора ответов.** Анализ истории, поиск и эмбеддинги всё ещё
используют прежнюю конфигурацию OpenAI и требуют `OPENAI_API_KEY`. Даже при локальном
генераторе поиск контекста может отправлять данные в OpenAI. Полностью автономный
локальный режим этим изменением не реализован.

## Локальное обучение выбранным ответам на Apple Silicon

Основной сценарий: «Обучать мой стиль» → занятие → «Обучить новую версию» →
слепое сравнение → «Использовать новую версию». Старые инструменты находятся
в «Дополнительно». Главная функция трёх ответов сохранена.

Занятие содержит до 10 случайных отрывков. Прогресс сохраняется в `learning/lesson.json`;
«Пауза» отменяет незавершённую генерацию, продолжение использует те же отрывки.
Скрытый настоящий ответ, будущие сообщения, рабочая память и профили в исторический
запрос не передаются. Карточка обновляется на месте; длинный контекст доступен страницами.
Выбор варианта, исправление или подтверждение настоящего ответа переводит к следующему
отрывку. Пропуск не создаёт учебный пример. Во время живой переписки оценивать ничего не нужно.

Перед первым занятием фиксируются до пяти независимых проверочных отрывков в
`learning/holdout.json` (минимум два). Они не пересекаются с ранее использованными
учебными источниками. Новые занятия и обучение используют только более ранние сообщения,
не пересекающиеся с проверкой. Удалённые источники не заменяются незаметно.

Кнопка обучения явно запускает 50 шагов QLoRA в фоновом процессе.
Источники: последний вариант с оценкой «Отправил бы», явно выбранный настоящий
ответ или собственное исправление (исправление имеет приоритет). Отрицательные
оценки сами по себе не создают целевой ответ. Выбирайте примеры обычного общения.
Случайные отрывки по-прежнему создаются существующей функцией тренировки.

Нужно хотя бы 8 обучающих и 2 проверочных примера после удаления пересечений
контекста и ограничения длины. Это технический минимум пробного запуска,
не достаточный объём для надёжного переноса стиля. Поздние отрывки используются
для проверки, их сообщения не попадают в обучение. При удалении исходных
сообщений или изменении выбранных ответов старый набор становится недействительным.

Окружение `.venv-mlx` устанавливается отдельно из `requirements-mlx.txt`.
Ожидается полностью скачанная модель `local_models/qwen3-4b-instruct-4bit`.
Перед обучением закройте отдельный `mlx_lm.chat`, чтобы освободить память.
MLX запускается дочерним процессом, работает без сети и обновляет веса адаптера
в четырёх последних слоях. Обучение учитывает только целевой ответ, а не текст
контекста. Слишком длинные примеры исключаются целиком.

Наборы сохраняются в `learning/reviewed`, адаптеры и измерения — в
`learning/mlx_runs`, журнал нового фонового процесса — в каталоге запуска `process.log`.
Статус и PID — в `learning/training_job.json`. После перезапуска проверяется идентичность
процесса; старый PID сам по себе не считается доказательством работы. Есть остановка,
защита от двойного запуска, общий GPU-lock для генерации и обучения. Отображаются
подготовка, обучение со счётчиком шагов, проверка и завершение/ошибка.
До и после измеряется ошибка на одинаковой проверочной выборке, сравниваются
хеши обучаемых весов. Успешный запуск имеет статус `trained_unapproved`.
Первоначальный запуск обучает новый адаптер от базовой модели на настоящих ответах
владельца. Доработка начинает с первоначального адаптера и сочетает выбранные ответы
с повторением исторических примеров. Старые адаптеры не перезаписываются.
Одновременные запуски заблокированы.

Новые занятия и слепое сравнение используют управляемый локальный генератор.
Модель запускается на время запроса; отдельный сервер или терминал не требуются.
Генерация трёх вариантов делает отдельные выборки одного ответа. Ошибка локального
процесса не переключает запрос на API. Старый раздел исторической тренировки
сохранён для совместимости и по-прежнему использует настроенный API-генератор.

Сравнение хранится в `learning/comparisons`: порядок двух ответов случайный и
зафиксирован, готовые ответы повторно не генерируются. Оценки сравнения не становятся
учебными примерами. Сравниваются предыдущая локальная версия (по умолчанию базовая)
и новая, а не локальная модель с OpenAI. Показывается число предпочтений каждой версии,
«обе подходят» и «обе плохие». Числа loss не заменяют оценку владельца.

После завершения сравнения можно явно применить адаптер к обычным трём ответам
этого диалога. Выбор и предыдущая версия хранятся в `learning/selected_model.json`.
Есть откат и возврат к прежнему настроенному генератору. До применения обычные ответы
сохраняют прежнюю маршрутизацию. Контрольная сумма реально загруженного адаптера,
версия и задержка сохраняются в запросе/журнале генерации. При отзыве учебного
примера или изменении источников адаптер блокируется до нового обучения.

Поиск памяти и анализ обычного диалога всё ещё могут использовать OpenAI;
новые занятия, сравнение и обучение выполняются локально. После изменения кода
нужен перезапуск бота; веса и данные не публикуются в Git. Автоотправка не включена.

На Apple M4 выполнена проверка MLX на искусственной переписке: пять шагов изменили
327680 параметров; проверены загрузка адаптера, сравнение, применение и откат.
В двух коротких запусках три варианта заняли около 4,8 и 14,8 секунды внутри MLX;
последний полный запрос с запуском процесса занял 15,6 секунды (без Telegram).
Задержка зависит от длины ответа и выборки модели. Также проверена остановка
настоящего дочернего процесса обучения по его идентификатору.
Это проверка механизма, а не результат обучения стилю владельца. Повторяемая проверка:
`.venv-mlx/bin/python -m scripts.check_style_pipeline --steps 5`.
Она использует временный workspace и не подключается к Telegram. Числовой отчёт
без переписки сохраняется в `local_models/style_pipeline_check.json`.
Живой интерфейс и полезность ответов на реальной истории нужно оценить владельцу.

### Первоначальное обучение по истории

В «Обучать мой стиль» есть «Сначала обучить на моей переписке». Сначала отдельный
CPU-процесс проверяет источники и длины токенизатором локальной модели. На экране
появляются количество примеров, распределение по периодам, даты и приблизительное
время. Кнопка «Обучить на этом наборе» запускает один полный проход (batch size 1,
число обновлений равно числу примеров). Ручные оценки для первого запуска не нужны.
Предварительный диапазон времени — грубая оценка, фактическое время хранится в run.json.

Выбирается до 512 пар из трёх хронологических частей пригодной истории. Сначала
исключаются слишком длинные пары, затем квоты перераспределяются при нехватке.
Используются реальные исходящие текстовые сообщения; неотправленные предложения
не входят в первоначальное обучение. Фиксированная проверка сохраняется; весь
обучающий контекст и ответы должны предшествовать её самому раннему источнику.
Поэтому «недавняя часть» означает недавнюю часть доступной для обучения истории,
а не сообщения после проверочной границы. Исходная история и оценки повторно
проверяются перед запуском, после обучения и перед использованием адаптера.

Версия, прошедшая техническую проверку генерации, автоматически включается только для занятий: её указатель хранится
в `learning/practice_model.json`, отдельно от `selected_model.json` обычных ответов.
Карточки показывают базовую модель / обучение на истории / доработку по оценкам,
дату и период. Существующая карточка с готовыми вариантами не перегенерируется;
подпись соответствует реально использованной версии. Новые занятия имеют квоты
3/3/4 с чередованием дополнительного отрывка. Пауза и перезапуск сохраняют прогресс.
Примеры первоначального набора допускаются в занятиях с явной отметкой.

Доработка загружает исходный адаптер, проверяет его хеш и совпадение весов перед
обучением. Исправления заменяют старые целевые ответы соответствующих ситуаций;
остальные исторические примеры берутся из первоначального набора. Происхождение
«отправленный ответ / исправление / одобренный вариант» сохраняется. В слепом
сравнении дополнительно можно отметить неправильную реакцию, выдуманные факты,
нехарактерные эмодзи и формулировки отдельно для каждого ответа. Это оценки владельца,
не запрет новых слов и не автоматическое доказательство улучшения.

Повторяемая проверка нового механизма:
`.venv-mlx/bin/python -m scripts.check_history_training`.
Два прохода по 8 синтетическим примерам проверяют обновление весов, загрузку
первоначального адаптера при доработке, фактическую генерацию и раздельные указатели.
Отчёт: `local_models/history_training_check.json`. Личная переписка не используется.
В предыдущей версии механизма на этом Mac проверка заняла 69,5 с: первоначальный проход 27,7 с, доработка 25,4 с;
по 8 обновлений весов. Loss на синтетической проверке: 6,94 → 1,42 → 0,88.
Один ответ до/после занял 3,68/3,40 с с запуском процесса; три ответа — 3,78 с.
Это измерения коротких искусственных примеров, не оценка качества личного стиля
и не точный прогноз времени обучения на 512 реальных ситуациях.

### Проверка окончательных ответов после обучения

Формат `qwen-final-v1` общий для подготовки набора, MLX-обучения и генерации.
Завершённый пустой thinking-блок входит в префикс; целевая маска охватывает только
настоящий ответ и токен завершения. Проверяется точное совпадение токенов префикса.
Скачанный шаблон модели не изменяется. Формат фиксируется в манифесте, запуске и запросе.
Новые обучения используют learning rate `2e-5`; старый набор нужно подготовить заново.

Генерация проверяет завершение по EOS, непустой текст, отсутствие служебных тегов,
шести последовательных повторов блоков 1–4 токенов и доминирования одного токена
более чем в половине ответа длиной от 32 токенов. Лимит — две попытки на требуемый
вариант. Неудачный результат не становится вариантом и не отправляется в API.
Причины сохраняются в receipt; в занятиях сохраняется и receipt неудачного запроса.

После обучения автоматически проверяются все закреплённые ситуации с seed 42 и
314159 для базовой модели и адаптера. Нет повторных попыток, которые могли бы скрыть
сбой в этой проверке. При пяти ситуациях нужны 10/10 технически корректных ответов
адаптера. Loss и хеш весов сами по себе не разрешают подключение. Отчёт с ответами,
временем, хешем адаптера и причинами отклонения находится в каталоге адаптера:
`quality_qwen-final-v1.json`; предыдущие диагностические отчёты архивируются.

Версия без успешной актуальной проверки недоступна для применения; занятия не
подменяют её базовой моделью и показывают причину недоступности. «Проверить без
переобучения» проверяет прежние веса.
При неудаче «Подготовить исправленное обучение» создаёт новый набор с теми же
источниками, без загрузки плохого адаптера. Полное обучение запускается только
после просмотра подготовленного набора обычной кнопкой. Прежние веса сохраняются.

Новые сравнения имеют суффикс `_qwen-final-v1`; старые файлы, ответы и оценки не
перезаписываются, старые кнопки не могут проголосовать в новом сравнении. Для сравнения
с базовой моделью используются уже проверенные ответы с одинаковым seed 42.
Это технический допуск, не автоматическая оценка естественности или сходства со стилем.

Проверка существующего адаптера на пяти закреплённых ситуациях после исправления
формата: 10/10 у базовой модели и 10/10 у адаптера, 43,2 с всего. Медиана генерации
одного ответа: 1,96/1,71 с соответственно, без загрузки модели. Существующие веса
не переобучались. Подготовлено отдельное сравнение без переноса прежних оценок.

### Два ответа обученной модели в занятиях

Новые занятия сохраняют `variant_count=2`: оба варианта создаёт текущая обученная
версия, прошедшая автопроверку. Без такой версии занятие не запускается. Основная
функция трёх ответов и отдельное сравнение версий сохраняют своё назначение.
Старые карточки с тремя вариантами и их оценки сохраняются; старые ответы базовой
модели не предлагаются повторно как варианты занятия.

В карточке доступны «Первый», «Второй», «Оба плохие», свой вариант и исторический
ответ. У каждого предложения независимо отмечаются неуместная реакция, выдуманные
факты, чужие эмодзи и фразы; повторное нажатие снимает отметку. Есть встроенная
справка. Вариант с отметками ошибок не допускается как положительный пример;
исправление владельца или настоящий исторический ответ остаются самостоятельными
целями обучения. «Оба плохие» не создаёт учебного ответа: можно исправить или пропустить.
Отметки ошибок не являются градиентным обучением на отрицательных примерах.
Выбранные ответы копятся, веса меняет отдельный запуск доработки.

## Границы беседы и пауза

Новые учебные пары разделяются по времени: по умолчанию промежуток от четырёх часов
начинает новую беседу. Порог задаётся отдельно для диалога в «Обучение и версии».
Это правило разрывает контекст и блок исходящих сообщений, но не присваивает метку
«не отвечать». Для проверки паузы занятия берут только окончание входящего блока,
после которого в истории видна следующая беседа; последующие тексты модели не передаются.
Край незавершённого экспорта не считается доказательством паузы.

В занятии локальная модель сначала сравнивает вероятности `REPLY` и `WAIT`,
не генерируя для этого свободный текст. Владелец может
подтвердить паузу или запросить два ответа. Подтверждённое действие хранится отдельно
от текстового ответа и попадает в дообучение как отдельная задача. Первоначальное
обучение содержит только подтверждённые историей действия `REPLY`; `WAIT` требуется
подтверждать владельцу. Старые карточки и оценки сохранены, но пары через границу
беседы исключаются из нового обучения. Старый адаптер сохраняет собственную
проверочную выборку; новую можно закрепить после предпросмотра, затем начать новое
первоначальное обучение от базовых весов.

Обычная генерация локальной моделью сначала проверяет необходимость ответа.
Решение `WAIT` показывается в боте с кнопкой явного запроса вариантов. Новые
сообщения перезапускают таймер простоя. Через пять минут локальная модель может
проверить паузу, а через 30 минут выполняется дозагрузка пропущенной истории даже
при неопределённом решении. Дозагрузка не запускает embeddings и обучение. При
пропуске перед уже обработанной контрольной точкой эпизодов автоматическая
пересборка запрещена: состояние помечается как требующее проверки.

```bash
API_ID=1 OPENAI_API_KEY=offline-test PYTHONDONTWRITEBYTECODE=1 venv/bin/python -m unittest discover -s tests -q
```

## Runtime audit (2026-10-11)
Normal dialog preparation imports/reconciles history and uses cached profiles only;
legacy episode embedding and full analysis require explicit `full_analysis=True`.
A scoped `reply_runtime.json` records minimal readiness. Existing nonzero episode
checkpoints are still validated; missing sources do not trigger silent rebuilds.
Idle catch-up performs history synchronization after 30 minutes, without local AI
classification or GPU wakeups. Legacy Telegram tools are constructed lazily and
hidden callbacks do not execute them.
Canceled lesson generation persists completed results but does not redraw an
advanced lesson card. GPU contention preserves training metadata and checkpoint
progress; jobs that never started are distinguished from resumable checkpoints.
Reply evidence reconciliation can skip unchanged history/deletion file revisions;
edits and deletions still trigger reconciliation.
`scripts.audit_replies --account ID --dialog ID --limit 10 --minutes 30` generates
protected historical replies before revealing actual targets to a separate API
analyst. It changes neither weights, owner ratings nor the learning queue. Reports
stay under the workspace's `reply_assistant/audits/`. API judgments are hypotheses.
`scripts.benchmark_local_worker --prefix` compares within-request KV prefix reuse.
This optimization remains experimental and disabled by default: a five-case test
reduced median inference time but did not preserve identical sampled replies.
